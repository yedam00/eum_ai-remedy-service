핵심요구사항) 다음의 기능을 playwright 테스트를 활용하여 TDD기반으로 구현할 것.
            1) 테스트 제외 라이브러리
                - jest
                - @testing-library/react

            2) 테스트 조건
                - timeout은 설정하지 않거나, 500ms 미만으로 설정할 것.
                - /chat-entry 페이지가 완전히 로드된 후 누르고 말하기 버튼을 클릭한 이후 테스트할 것.
                    - 페이지 로드 식별 요구사항: 고정식별자 data-testid 대기 방법
                    - 페이지 로드 식별 금지사항: networkidle 대기 방법
		    - microphone 권한('microphone')을 자동으로 허용 설정할 것.

            3) 테스트 로컬스토리지 조건
                - 성공 시나리오
		  1. /chat-entry 접속하고 누르고 말하기 버튼을 클릭한 후, VoiceInputSheet 모달 오픈
		  2. 마이크 입력에 따른 audioLevel 수치 변화 및 title 실시간 텍스트 반영 확인
		  3. audioLevel이 0이 된 후부터 2초 무음 감지 시 VoiceInputSheet이 'Success' 상태로 전환
		  4. 모달이 닫히며 /chat 페이지로 라우팅 이동
		  5. /chat 페이지의 AI SpeechBubble 아래 사용자의 <SpeechBubble /> 영역에 입력된 사용자의 음성 텍스트 노출 검증	

                3-2) 실패/폴백 시나리오
                    1. Web Speech API 미지원 브라우저 Mocking
      		    2. 2초 후 Fallback 텍스트("배가 쑤시듯이 아파요") 생성 -> Success 전환 -> /chat 페이지 이동 -> speech-bubble 노출 검증

핵심요구사항) step-by-step 기능 구현
	    1) window.SpeechRecognition 기반 음성 인식/audioLevel 분석 로직 구현.
	    2) 음성 인식 텍스트(transcript)를 VoiceInputSheet의 title에 실시간 바인딩할 것.
	    3) audioLevel(0~100) 수치를 VoiceIndicator 컴포넌트로 전달하여 비주얼라이저 연동할 것.
	    4) 음성 입력 후 2초간 무음 유지 시 VoiceInputSheet의 state를 'Success' 상태로 전환시킬 것.
	    5) 모달 닫기 및 /chat 페이지 이동
		    - VoiceInputSheet이 Success 상태로 전환된 후 모달을 닫을 것.
		    - Next.js useRouter를 사용하여 인식된 음성 텍스트(예: "두통이 있어요")를 파라미터로 전달할 것.
		    - /chat 페이지에서는 useSearchParams()로 해당 텍스트를 가져와 AI 질문 아래 사용자 <SpeechBubble variant="user" /> 영역에 즉시 노출시킬 것.
